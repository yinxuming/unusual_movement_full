# 股票严重异动监控-实现方案

## 一、需求概述

实现一款股票严重异动监控工具，用于监控A股股票涨幅异动情况，提前预警哪些股票即将进入异动监管。

### 1.1 异动监管规则
| 规则类型 | 时间窗口 | 涨幅阈值 | 适用范围 |
|---------|---------|---------|---------|
| 100异动 | 近10个交易日 | 累计涨幅 ≥ 100% | 全A股（严重异常波动） |
| 200异动 | 近30个交易日 | 累计涨幅 ≥ 200% | 全A股（严重异常波动） |

> **注意**：10天100%/30天200%是"严重异常波动"规则，适用于全A股（包括主板、创业板、科创板），不同于"异常波动"（3天20%偏离值）规则。

### 1.2 核心功能
1. **异动监控**：监控A股TOP涨幅股票接近异动情况
2. **提前预警**：默认提前5天（T+0 ~ T+4），可配置
3. **结果展示**：股票代码、名称、最新涨幅、当日及T+1~T+4各天的异动触发涨幅限制
4. **部署方式**：支持GitHub Pages部署，纯前端运行，不依赖本地服务端

## 四、核心算法设计

### 4.1 异动计算逻辑

```
输入：股票历史收盘价序列（至少30个交易日）
输出：T+0 ~ T+4 各天的异动触发涨幅限制

算法流程：
1. 获取最近30个交易日的复权收盘价 [p1, p2, ..., p30]
   p30 = 最新收盘价（当日）

2. 计算10日异动触发涨幅：
   for i in 0..4:  # T+0 到 T+4
       # 10天窗口：取最近10天的最低价作为基准
       base_10 = min(p21, p22, ..., p30)  # 最近10天最低价
       current = p30
       
       # 假设第i天涨幅为x%，则价格为 current * (1+x%)
       # 要求：(current*(1+x%) - base_10) / base_10 < 100%
       # 解得：x < (base_10 * 2 / current - 1) * 100
       # 但这是简化版，实际需考虑基准价可能随时间滑动
       
       # 正确做法：模拟未来i天的价格走势
       # 第i天后，10天窗口变成 [p(21+i) ... p30, future_1, ..., future_i]
       # 基准价 = min(原窗口内的价, 未来i天的价格)
       # 如果假设未来i天连续涨停，基准价就是原窗口最小值
       trigger_10[i] = 计算触发100%所需涨幅

3. 计算30日异动触发涨幅：同理，窗口为30天
```

### 4.2 触发涨幅计算公式（关键算法）

```javascript
/**
 * 计算某股票在未来第n天的异动触发涨幅限制
 * 
 * @param {Array} prices - 最近N个交易日的收盘价数组（从旧到新）
 * @param {number} windowSize - 异动窗口（10或30天）
 * @param {number} threshold - 异动阈值（100%或200%即1.0或2.0）
 * @param {number} futureDay - 未来第几天（0=当日, 1=T+1, ...）
 * @returns {number} 触发涨幅限制百分比，若已触发返回0或负数
 */
function calcTriggerLimit(prices, windowSize, threshold, futureDay) {
    // 1. 取窗口期的历史价格
    const windowPrices = prices.slice(-windowSize);
    const currentPrice = windowPrices[windowPrices.length - 1];
    
    // 2. 窗口期内最低价（基准价）
    const basePrice = Math.min(...windowPrices);
    
    // 3. 当前已经涨幅
    const currentGain = (currentPrice - basePrice) / basePrice;
    
    // 4. 若已经触发，返回特殊标记
    if (currentGain >= threshold) {
        return 0; // 已触发
    }
    
    // 5. 计算futureDay后的情况
    // 假设未来每天价格不变（保守估计，基准价不变）
    // 则触发需要的涨幅 = (threshold - currentGain) * 100
    const remaining = (threshold - currentGain) * 100;
    
    return Math.max(0, remaining);
}
```

### 4.3 排序策略
- **主排序**：按当日触发值升序（越小越紧急，排越前）
- **次要排序**：按当前涨幅降序（涨幅大的优先关注）

## 八、关键技术点与注意事项

### 8.1 复权处理
- 必须使用**前复权**价格计算，否则除权除息会导致涨幅计算失真
- 东方财富API支持 `fqt=1` 参数获取前复权K线

### 8.2 交易日历
- 异动规则中的"10天""30天"指的是**交易日**非自然日
- 需基于实际K线数据计算，无需额外维护交易日历

### 8.3 并发控制
- TOP 100股票需要逐个获取历史K线，约100次HTTP请求
- 需实现并发控制（如同时最多10个请求），避免浏览器限流
- 可考虑分批加载，先展示已计算完成的股票

### 8.4 CORS问题
- 本地开发：使用Python代理服务器（server.py）转发API请求，支持localhost和局域网IP访问
- 生产环境（GitHub Pages）：直接调用东方财富API，降级使用JSONP
- API不可用时：自动切换到模拟数据模式，保证UI可测试

### 8.5 GitHub Pages限制
- 仅支持静态文件，无服务端逻辑
- 所有计算在浏览器端完成
- 无本地存储限制，可使用localStorage做简单缓存
